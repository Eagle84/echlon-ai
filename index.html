Echlon AI

A virtual software company staffed by AI agents. Give it a business goal; a CTO plans it, you approve the plan, a Dev Lead delegates to specialist engineers, and deterministic checks decide whether the work actually ships.

Claude Agent SDK TypeScript React + Three.js Human-in-the-loop

How a run works

Plan→ Approve (you)→ Execute→ Validate→ Deliver

The CTO turns your goal into a machine-readable task breakdown, with an owner and explicit acceptance criteria per task. Nothing is built until you approve that plan. The Dev Lead then delegates each task, reviews the returned work against its acceptance criteria, and sends it back if it falls short. Finally the workspace is validated by actually running lint and tests — not by asking a model whether it went well.

The org chart

TierRoleResponsibility
ExecutiveCTO Turns the goal into a plan with owners and acceptance criteria. Holds no file-writing tools — it plans, it does not build.
ManagementDev Lead Delegates each task, reviews every result against its criteria, and re-delegates on failure. Writes no code itself.
Execution Frontend · Backend · Android · QA · Automation Each receives exactly one task with a fresh context and the tools for its discipline.

Roles are data, not code — a YAML file with a prompt, a model tier, a tool list and skills. Adding a department is a new file, not a new module.

What makes it trustworthy

Deterministic gates

Lint and tests are executed as real commands. An empty workspace fails validation instead of quietly reporting success.

Two-level self-correction

The Dev Lead reviews each task before accepting it; the validator loops fixes back to the team up to three times.

You hold the gate

No execution starts before you approve the plan — and you can reject it with feedback, or stop a run mid-flight.

Budget aware

Per-phase and per-run spend caps, with live cost and token usage broken down by model.

Honest reporting

Per-employee retrospectives are computed from recorded activity — files written, commands run, review verdicts — not generated opinion.

Context discipline

Each agent gets only its own task spec. No agent inherits another's transcript, which keeps runs cheap and focused.

The office view

Every agent instance is a person in a 3D office. New hires walk in through the entrance and take a briefing in the Dev Lead's office before sitting down at a desk that appears for them. Finished work is reported face to face, and the review verdict appears above the Dev Lead's head. There are daily standups in the meeting room, coffee breaks, colleagues walking over to consult each other, and an inner monologue about the task each person was actually assigned. When the project ships, the team celebrates and the hired staff head home — leaving their desks behind.

It is a genuine view of the run, not a decoration: every movement is driven by the same event stream that fills the text feed, and clicking a person opens their transcript and retrospective.

Under the hood

  • Engine — a phase state machine over the Claude Agent SDK; one query per phase, subagents composed at runtime from the role registry.
  • Skills — a local bank of SKILL.md skills, materialised per run so each role only carries what it needs.
  • Dashboard — Fastify + WebSocket streaming a normalised event log to a React UI; full replay on reconnect.
  • Visualisation — react-three-fiber and Rapier; the floorplan is generated from the org chart, so new roles get rooms automatically.
